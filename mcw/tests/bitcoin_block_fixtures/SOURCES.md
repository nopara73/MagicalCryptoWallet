# Bitcoin block and Merkle conformance provenance

The first-party Rust implementation is independently written from the Bitcoin
wire specification and Bitcoin Core v30.0 behavior. No reference implementation
is linked, bundled or called by mcw. Reference programs and downloaded sources
are development-only evidence in an ignored directory.

`manifest.json` records the exact SHA-256 and byte length of every primary
reference file, the URLs at the fixed `v30.0` tag, and fixture file hashes.
`BITCOIN-CORE-LICENSE.txt` preserves Bitcoin Core's MIT copyright and license
notice for its extracted public block vectors and test/reference material.

`blocks.tsv` has 14 complete raw blocks: ten Core testnet filter vectors,
mainnet/Signet/regtest genesis reconstructed from Core's published fields and
the unchanged genesis transaction, and getBlock13b8a (nine transactions).
Each row records the independently checked display hash, transaction count,
witness count, stripped/total bytes, weight, raw bytes, raw txids and wtxids.
The set contains four witness transactions. It is public chain data, never
user wallet material.

`partial.tsv` has 33 complete partial-tree payloads, generated by the independent
Python recursive reference with no matches, all matches, and second/last matches
where applicable. Hash order, flag bit order, exact serialized bytes, Merkle
root, matched indices and used flag-bit count are recorded. Core's actual Python
CPartialMerkleTree and CMerkleBlock deserialize and reserialize every vector.
The nine-transaction case reproduces Core's second/last matched transaction test.

The offline Rust suite includes all these vectors, all masks for 1–7 leaves,
CompactSize boundary counts, exact and prefix streams, every truncated prefix
of synthetic blocks/partial trees, malformed counts/flags/padding, duplicate
real sibling mutations at leaf/internal levels, wrong roots, proof shape/order,
aggregate/per-transaction memory bounds, compact sign/overflow/canonical behavior,
and 4,000 deterministic malformed-data panic checks.

`bitcoin_block_reference.py differential` compares actual Rust source via the
test-only driver against Python hashlib, arbitrary-precision target arithmetic,
independent recursive Merkle/partial-tree algorithms, and unchanged Core Python
codec bodies. Its AST adapter excludes only two unused utility imports and an
unrelated top-level utility assertion; it supplies no substitute utility stubs.
It runs 8,304 deterministic comparisons with seed `0xB10C37`. The reference does
not use Core's block `is_valid` function or claim proof-of-work/consensus coverage.

Prepare only from the exact downloaded primary sources, verify their hashes
against the manifest before using them, and keep downloaded files ignored:

    python mcw/tests/bitcoin_block_reference.py prepare --references .artifacts/bitcoin-block-evidence/references
    ./mcw/tests/bitcoin_block_verify.ps1 -ReferenceDirectory .artifacts/bitcoin-block-evidence/references

`bitcoin_block_inventory.py` reads immutable Git blobs. Its snapshot and complete
mechanical caller/package matches are `inventory.json` and `managed_callers.tsv`.
Those files describe retained managed code; the Rust codec itself has only std
plus the actual first-party bitcoin_wire/bitcoin_encoding source dependencies.
Native production integration, upstream package removal and four non-Windows
native executions are outstanding work.

## Bounded cache header identity

`headers.tsv` contains 256 deterministic synthetic 80-byte headers: zero bytes,
all-ones bytes, ascending bytes and 253 pseudorandom inputs with seed `0x0E00`.
`bitcoin_block_header_reference.py` checks the existing hash-pinned, unchanged
Bitcoin Core v30.0 `CBlockHeader` against Python hashlib, then stores raw and
display-order hashes. Its input/reference/fixture hashes are in `manifest.json`.
No user block, wallet, key or network connection is used for these new vectors.

`header_conformance.rs` exercises the exact 80-to-32-byte native
application service, all short lengths, oversized inputs and hash byte order.
`bitcoin_block_header_probe.cs` is an ignored-output test child of the actual
mcw host using its actual managed connection and production cache source. It
compares all synthetic hashes with Core/hashlib and the retained NBitcoin
reference, checks cache/error/retry behavior and retries preserved bytes after
actual host binding teardown. The verifier freezes real source and distinguishes
an applied shared dispatch proposal from published incorporation; test execution
does not by itself verify publication. NBitcoin remains a retained data mapping
and independent test reference, with no fallback hashing path in the cache.
