# Network routing

Bitcoin headers, compact filters, full blocks, and the general mempool feed connect directly. Blocks are requested from randomly selected block-serving peers after filters are matched locally; filter false positives still produce block downloads. This reduces Tor bandwidth, while exposing the client IP and requested block hashes to those peers. False positives and random peer selection do not hide the IP address.

The direct pool targets six connections and requires five compact-filter peers. It receives the public mempool without sending wallet addresses or filters to peers. Transaction downloads are shared across the pool, with bounded reservations and retries after timeout, disconnect, or `notfound`. Block-only mode disables this feed.

With Tor enabled, a separate pool handles wallet broadcasts and propagation confirmation. It cannot supply blocks and does not download mempool transaction bodies. It targets four peers: two for announcing a broadcast and two for independent propagation confirmation. It starts on the first broadcast, then remains available. Transaction inventory announcements still use Tor for propagation checks. Direct receive-only peers cannot serve the wallet's broadcast store or confirm its propagation. The pools reserve distinct peer hosts, including aliases using another port or IPv4-mapped IPv6, and retain network-group diversity limits. Tor-disabled sessions, including local regtest, share the direct pool for broadcasts too.

Transaction-specific CPFP lookups and CoinJoin requests also use Tor when enabled. Each request identity keeps its existing circuit isolation. CPFP requests share in-flight downloads, retain successful results, wait briefly before retrying failures, and skip scheduled requests that become ineligible while waiting. Cancelled CoinJoin waits are removed before polling; polling failures back off. HTTP retries dispose failed responses, respect `Retry-After`, and stop at the caller's deadline.

Public prices, fee estimates, release announcements, authenticated installer downloads, and Tor outage reports connect directly. Installer signatures, announcement authentication, URL restrictions, and checksum verification still apply. Release checks work with Tor disabled; regtest skips them. There is no public-data Tor setting. Old configuration files containing `UseTorForPublicData` remain readable, but the obsolete value is ignored and omitted when saved.

Discovery uses four crawlers per active pool, a bounded deduplicated queue, and cooldowns. It tries cached peers and hardcoded seeds before DNS and pauses once enough connections and spare candidates exist. Separate Peers-public.json and Peers-wallet.json caches contain at most 128 recent addresses and service hints, expire after seven days, and recheck capabilities during each handshake. These files contain no wallet addresses, transaction IDs, or selected block hashes. Broadcast peers are ranked without a compact-filter bonus.

Coordinator public fee queries connect directly, independently of publishing an onion service. Onion destinations require Tor. Exact loopback destinations (localhost, 127.0.0.1, and ::1) connect locally.
